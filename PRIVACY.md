# Privacy Policy — CensoSenso MCP

## Current scope

CensoSenso currently exposes two operational transports:

- local **STDIO**;
- public **Streamable HTTP** at `https://censosenso.poderdapalavra.org/mcp`.

The service provides read-only access to Brazilian public statistics and geographic data from IBGE. The current public endpoint does not require a CensoSenso account, login or API key.

## What CensoSenso processes

Tool arguments are used only to execute the requested operation and to build requests to official IBGE sources or to read versioned official snapshots packaged with the server.

The application does not maintain a user-profile database.

### STDIO

In local STDIO mode:

- the request cache is in memory and TTL-bound;
- no hosted CensoSenso service receives the MCP traffic;
- responses carry provenance metadata for the official data source.

### Public HTTP Worker

The Cloudflare Worker receives the HTTP request needed to operate the MCP transport.

The current implementation may process:

- request method and path;
- standard Cloudflare request metadata needed by the platform;
- `CF-Connecting-IP` in memory for per-client rate limiting;
- MCP session id generated by the server for linking protocol messages within a handshake;
- tool name and success/error counters in the `USAGE` Durable Object.

The application code does **not** persist tool argument values, query contents or tool results in the `USAGE` counters.

Worker request logs emitted by the application contain method, path, status and elapsed time; they do not intentionally log tool argument values or returned datasets.

Cloudflare, as the hosting provider, independently processes network and service telemetry according to its own service terms and policies.

## Advanced analytics

The code contains optional support for a Workers Analytics Engine binding. That binding is **not enabled in the current production deployment**.

When absent, the MCP result is unchanged; only advanced telemetry is disabled.

If it is enabled in the future, the deployment documentation and this privacy notice must be updated before treating that configuration as production.

## Authentication

The code supports optional Bearer authentication through `API_KEY`, but the current public endpoint is deployed without that requirement.

OAuth is not enabled.

Any future authentication change must be documented together with its data-processing implications.

## Upstream requests

Queries are translated into requests to official IBGE APIs and official IBGE data sources. CensoSenso does not need to forward a CensoSenso user identity to IBGE.

Depending on the tool, the upstream request can contain the territorial code, table, indicator, period or other public-data query parameters required to answer the request.

## Versioned snapshots

Some thematic territorial listings use official IBGE/GeoFTP snapshots versioned in the repository instead of a live WFS. Those files contain public territorial data, not user data.

## Provenance metadata

Successful responses can expose:

- official source name;
- canonical source URL;
- reference period/vintage;
- extraction timestamp;
- citation text;
- attribution URLs.

The out-of-band metadata namespace is:

```text
io.github.hilaliskandar.censosenso/provenance
io.github.hilaliskandar.censosenso/attribution
```

## Data license

Statistical and geographic data returned by the service comes from IBGE and is Brazilian public open data. CensoSenso is not endorsed by IBGE.

## Retention

CensoSenso itself currently has:

- in-memory TTL cache for live source responses;
- aggregated usage counters in the `USAGE` Durable Object;
- Cloudflare-hosted observability/logs as configured for the Worker.

There is no CensoSenso user-account database.

Because Cloudflare platform retention is controlled by the hosting account and product configuration, readers should not infer a platform retention period that is not stated in this repository.

## Security and contact

For security reporting, follow [SECURITY.md](SECURITY.md).

A dedicated public operational contact address has not yet been configured. Repository issues are the current public project channel.


## Metrics access

Aggregated counters stored in the `USAGE` Durable Object are not intended as a public data product. The Worker keeps `/metrics` private by default:

- without `METRICS_API_KEY`, `/metrics` responds with 404;
- with `METRICS_API_KEY`, the route requires the matching Bearer token;
- this policy is independent from the optional `API_KEY` used by the MCP endpoint.

This access control does not change the data minimization rule above: tool argument values, query contents and returned datasets are not intentionally persisted in the `USAGE` counters.
